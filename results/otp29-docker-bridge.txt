  WRONG cookie + NO client cert                  -> false

=> inet_tls with verify_peer + fail_if_no_peer_cert makes the client certificate the
   authentication: no cert, or a cert from another CA, is refused during the TLS
   handshake, before the cookie is ever checked. The cookie is still checked after
   TLS (wrong cookie + valid cert is refused), so both are required. Any certificate
   from the trusted roots is accepted: the certificate is not tied to the node name.
=> With verify_none the cookie is again the only check: TLS then gives confidentiality
   on the wire, not authentication of the peer.
=> TLS does not change where the node listens: the listener stays on 0.0.0.0. Binding
   to loopback is a separate control, inet_dist_use_interface, and it applies to
   inet_tls unchanged (B2).
=> Not measured here: post-handshake client authentication (TLS 1.3), which OTP ssl
   does not implement (erlang/otp#9667); a second physical host.
